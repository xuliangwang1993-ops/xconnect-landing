    Pod 实况

    订单 · 发起人负责关单

    订单是「工厂发起 → 派到 pod → 交付 → 发起人关 pod」这一段的凭证。关单条件写在 close_policy，账单以 RunPod 官方 billing 为准，我们自己只挂一个按 $/hr 估算的参考值。

    这段链怎么走

    1. 建单小助手把配方 + 一句话写成 build/private/orders.json
    2. 派单build/06_pod.py 读 RUNPOD_KEY（只读环境变量，不落盘）拉 pod 实况，与订单对账
    3. 干活03/05 两站的重活走 ffmpeg + GPU；iSH 这边只保留 06 验收
    4. 交付成片落 runs/<id>/05_export/，QA 全过才写 delivered
    5. 关单按 close_policy 由发起人关 pod；POST /pods/{id}/stop 是只读 key 拒的那一步，界面上标成 pending，不假装已经关了

    交接账本

    #站产物 → 上游闭合缺

    闭合 = 上一站 outputs 里的 sha256 与本站 inputs 记的一致。

    一句话 → 配方打分 + 命中词 + 证据。本地规则匹配，不调模型。

    派单预览

    匹配到已实测配方后，小助手把话写成订单，交给 06_pod.py 去对账。
